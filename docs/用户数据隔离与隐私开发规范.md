## 2. 数据库层行级隔离

**强制机制**（`ai_butler/core/db.py`）：

1. 归属账号的业务实体**必须**继承 `UserScoped`（提供 `user_id` 列）；
2. 所有查询必须经 `session_scope(user_id=...)` 执行。未绑定 `user_id` 却访问
   `UserScoped` 实体 → 抛 `RowLevelIsolationError`，**查询不会下发**；
3. 绑定后由 SQLAlchemy `do_orm_execute` 事件**自动注入** `user_id` 过滤条件，
   业务代码无法「忘记写 WHERE」；
4. 写入由 `before_flush` 钩子校验：待写入行的 `user_id` 必须等于当前绑定账号，
   否则抛错——**堵死把 A 的数据写进 B 账号的路径**。

**公共实体例外**：`Base`（无 `user_id`）用于计划书明确无用户 ID 的公共域
（素材溯源库 / Agent-Wiki 公共 Workspace）。两者的区分是硬边界，不得混淆。

**禁止**：裸 `text()` SQL 绕过抽象层；在公共实体上挂 `UserScoped`；
传入空字符串或占位符作为 `user_id`。

## 3. Agent-Wiki 公私库隔离

| 规则 | 内容 |
|---|---|
| 公共 Workspace | 全用户可读；页面**不得**携带 `user_id` |
| 用户私有 Vault | 绑定 `user_id`；页面**必须**携带且须等于目标账号 |
| 检索 | 只合并「公共 Workspace + 当前用户 Vault」，**绝不遍历他人 Vault 目录** |
| 编译 | 公共库与私有库各自独立编译，作用域目录不混 |

细节见《Agent-Wiki 知识库开发规范》。

## 4. 统一文件存储隔离

`ai_butler/core/storage.py`：

- 全局作用域：`workspace / logs / backups / exports`——**不得携带 `user_id`**；
- 用户作用域：`vault/{user_id}`——**必须携带 `user_id`**，绝不跨账号；
- **路径穿越防护**：`..`、绝对路径、分隔符注入、空名一律拒绝；
- 版本备份与项目回溯同样受隔离约束：只备份指定作用域，备份 A 的 Vault 不会包含 B 的文件。

## 5. 账号与会话

| 项 | 规则 |
|---|---|
| 口令存储 | bcrypt 加盐哈希；先 SHA-256 预哈希以支持任意长度；**数据库无明文** |
| 隐私字段 | Fernet 对称加密独立存储，密文自带随机 IV，同一明文两次密文不同 |
| 会话凭证 | JWT(HS256) + Redis 登记表；`user_id` 与 `device_id` 必填 |
| 空闲失效 | 超过空闲阈值无交互 → 吊销，返回机器可读 `SESSION_EXPIRED` 供客户端弹窗重登 |
| 自动刷新 | 凭证剩余有效期低于刷新余量时无感换发，旧凭证即刻吊销 |
| 多端与踢下线 | 以 `(user_id, device_id)` 登记；`revoke_all_for_user` 一次性吊销全部设备 |
| 未登录 | **所有业务接口拒绝执行**；公开路径白名单只有基础设施探活 `/health` |

## 6. 日志脱敏

**两层脱敏，缺一不可**：

1. **字段级**（结构化日志）：密钥类（password / token / secret / api_key / credential 等）**整体抹除**，
   不做掩码；手机号 / 银行卡 / 位置**掩码**，保留排障粒度；
2. **文本级**（自由文本兜底）：正则扫出手机号与银行卡号并掩码，
   兜住「手机号出现在 URL 或异常信息里」的场景。

**红线**：

- `user_id` 是计划书**明确要求保留**的排障字段，脱敏时不得抹掉；
- 请求日志**只记元数据**（方法、路径、状态、耗时、user_id、客户端），
  **不记请求体、不记查询串**——两者都可能携带口令或令牌；
- 路径本身也要过文本级脱敏（手机号可能出现在 URL 中）。

## 7. 离线链路红线（P10）

- Harness 离线链路**严禁访问未脱敏用户私有 Vault 原始数据**；
- 日志进入 Harness 前必须完成隐私脱敏；
- `MEMORY.md` 只存缺陷与解决方案，**不存任何真实用户隐私**；
- 训练集构建必须剥离用户身份隐私；私有 Vault 原始隐私**禁止**进入训练集，公共 Workspace 可用；
- 人工审批后台只能按 `user_id` 查看对应账号业务，**禁止批量遍历**全部用户隐私，且不能导出完整隐私。

## 8. 开发自检清单（提交前逐条核对）

- [ ] 新增业务表是否继承 `UserScoped`？公共域是否确认无 user_id？
- [ ] 所有查询是否都经 `session_scope(user_id=...)`？有没有裸 SQL 绕过？
- [ ] 有没有可能把非当前账号的 `user_id` 写进库？
- [ ] 口令是否加盐哈希？隐私字段是否独立加密存储？
- [ ] 日志里有没有明文手机号 / 密码 / 银行卡 / 完整位置？`user_id` 是否保留？
- [ ] 未登录请求是否被拒绝？会话失效是否终止业务链路？
- [ ] 检索是否只合并「公共 + 本人」，有没有跨用户读取？
- [ ] 备份 / 导出 / 编译产物是否可能夹带他人数据？
- [ ] 离线链路的输入是否已完成脱敏？
